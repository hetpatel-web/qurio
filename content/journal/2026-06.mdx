## What I Worked On

I focused on turning the Local AI Lab from a vague idea into working experiments. That included getting `n8n -> Ollama` communication running on the home server and clarifying the structure of Qurio itself.

I also started cleaning up the content system so notes, experiments, builds, the journal, and the Now page each have a clearer role. That work now has a central anchor in [Qurio Site](/builds/qurio-site).

## What I Learned

- Clear constraints create better notes.
- I remember more when I document right after building.
- A small project with sharp scope teaches more than a broad plan with no output.
- Most workflow problems show up in request formatting and data handling before they show up in model behavior.

## What Changed

I am focusing less on collecting options and more on finishing small experiments. That has made progress feel quieter but more real.

The project context is now more explicit, and the content system feels easier to reason about. Notes, experiments, builds, the journal, and the Now page each have a clearer purpose instead of feeling like loosely related sections.

## Wins

- First working `n8n -> Ollama` workflow on the home server.
- Clearer understanding of Docker, Ollama, and API request structure.
- Better definition of how Qurio should organize experiments, notes, builds, and monthly reflection.

## Challenges

- Invalid JSON caused by multiline content.
- Incorrect body format when using Form-Data instead of JSON.
- Boolean versus string mismatches such as `false` versus `"false"`.
- Keeping documentation structure consistent while the project is still taking shape.

## Next Focus

Keep using [Qurio Site](/builds/qurio-site) as the source build entry for homepage work, philosophy notes, and content-system improvements.

The next useful layer is connecting the site structure more clearly to the long-term philosophy so future work compounds instead of scattering.
