# Local AI Lab 002: First n8n to Ollama Workflow

## Objective

Send content from n8n to a locally hosted Ollama model and receive an AI-generated summary.

## Hypothesis

If n8n sends properly formatted JSON to Ollama, then a local model should be able to return a structured response that can be reused inside an automation workflow.

## Workflow

```text
Manual Trigger
    ↓
Set / Input Content
    ↓
HTTP Request
    ↓
Ollama
    ↓
qwen2.5:3b
    ↓
Structured Response
```

## Result

Success.

n8n successfully passed content to Ollama running `qwen2.5:3b` on the home server.

The model returned a structured response containing:

* Summary
* Key takeaways
* Action items
* Follow-up questions

## Challenges Encountered

* Invalid JSON caused by multiline content
* Incorrect body format using Form-Data instead of JSON
* Boolean type mismatch for the `stream` parameter

## What I Learned

* APIs often require strict JSON formatting.
* Data types matter. A string like `"false"` is not the same as a boolean `false`.
* Building prompts from separate instruction and content fields creates more maintainable workflows.
* Streaming responses can be useful for real-time output, but they are harder to process in automation workflows.

## Why This Matters

This experiment moves the setup beyond a simple connectivity test.

The workflow can now send meaningful content into a local model and receive output in a format that is useful for note-making, review, and future automation.

## Conclusion

The experiment was successful.

The main challenge was not model quality or infrastructure, but request formatting. Once the payload structure and data types were correct, the workflow behaved as expected.

This confirms that local AI summarization can be used as a practical step inside n8n workflows.
